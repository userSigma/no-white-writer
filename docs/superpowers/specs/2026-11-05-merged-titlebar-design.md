# 合并式自绘标题栏设计

日期：2026-11-05

## 目标与已确认要求

将应用从系统默认标题栏切换为自绘标题栏。用户进一步指定：自绘标题栏必须与原有顶栏合并，不能再叠加一条；主界面左侧显示品牌图标和应用标题，写作界面左侧显示折叠侧栏与返回主页按钮，顺序保持“折叠/展开目录 → 返回主页”。

本设计取代 PLAN.md §3 Q18 中“不自绘标题栏”的旧决策。其余数据安全、中文输入法、纯白/纯黑及自定义主题约束不变。实施与验证全程不使用子代理，不提交 Git，不覆盖先前未提交改动。

## 方案选择

采用“隐藏原生标题栏 + 自绘合并顶栏 + 保留系统窗口边框能力”。不采用完全移除窗口框架、再自行实现所有边缘缩放与阴影的方案，减少原生行为回归。沿用现有 window_manager 0.5.2，不新增运行时依赖，不修改包缓存。

## 布局

### 通用规则

- 只有一条约 36 逻辑像素高的窗口顶栏，跟随当前主题的底色、文字与细分隔线；不使用额外的系统彩色标题区。
- 最右侧为自绘最小化、最大化/还原、关闭按钮，每个约 46×36 逻辑像素。图标、工具提示与无障碍名称完整；有 hover、pressed、keyboard-focus 状态，关闭按钮悬停使用明确的危险色。
- 页面功能按钮和窗口按钮不是拖动区域；标题与剩余空白区域可以拖动窗口，双击切换最大化/还原。
- 标题过长省略，不挤压三个窗口按钮。窗口最小尺寸仍为 900×600，保留已有 DPI、位置、尺寸与最大化记忆。

### 主界面

`[品牌图标 不白写作] [可拖动空白] [排序 设置 新建] [— □ ×]`

现有排序、设置和新建操作纳入同一顶栏。原有“全部作品”、作品数和累计字数保留在书架内容工具区；搜索及网格/列表切换仍可用。不再保留与自绘标题栏并排重复的旧页面顶栏。

### 写作界面

`[折叠/展开目录 返回主页] [可拖动空白] [保存状态 / 字数] [— □ ×]`

- 不在左侧重复显示品牌、书名或额外标题。
- 将现有导航与轻量保存/字数状态放入该顶栏，移除正文中重复的顶层状态行和侧栏为旧导航预留的占位。
- 宽屏目录折叠、展开及动画过程中，导航与窗口按钮始终可用，且不受侧栏裁剪/IgnorePointer 影响。
- 窄屏第一个按钮改为打开/关闭目录浮层；返回主页顺序不变。目录保持唯一载体，不复制 ChapterPane，不破坏内联草稿、焦点及滚动状态。

### 其他窗口状态

重复实例提示也必须具有自绘标题栏及可用的关闭按钮，不能隐藏系统标题栏后留下无操作入口的窗口。弹窗的保存/取消规则不变；原生 Alt+F4 继续进入同一退出守卫。移动端和当前不支持桌面窗口的平台不显示桌面窗口控制按钮。

## 交互与安全

- 最小化与最大化/还原通过平台抽象调用 window_manager；外部最大化/还原事件须更新按钮图标，不能只维护点击后的本地猜测值。
- 关闭发出正常的可取消窗口关闭请求，绝不直接调用 destroy/quit 绕过 AppLifecycleListener。
- 复用现有退出路径：导出进行中、中文输入法组词、未完成内联草稿、设置持久化和保存失败确认继续有效。测试应覆盖自绘关闭入口而不只覆盖原有系统消息。
- 保留任务栏的窗口标题更新和 Alt+F4；不使用 window_manager.getTitle() 读取中文标题。
- 保留系统边缘缩放与拖动贴靠。Windows 11 最大化按钮悬停的系统分屏菜单不作为本轮承诺；不为其引入额外非客户区原生改造。

## 实现边界

- 共用的自绘顶栏、拖动区域及三个窗口按钮作为独立 UI 组件；主界面和写作界面传入各自的导航/操作内容。
- window_manager 的 import、窗口初始化、拖动与窗口状态监听继续留在 core/platform 边界；UI 通过可替换的平台接口调用，便于 widget 测试。
- 不改作品目录结构、正文、编号或导出格式，不做无关重构。PLAN.md 只针对本轮标题栏决策进行必要同步。

## 验收与交付

1. 测试先行：原生标题栏隐藏配置；两个页面仅一条合并顶栏；主界面品牌、写作界面导航顺序；窗口操作、真实拖动与双击；最大化事件同步；关闭入口与保存/IME/导出守卫；窄屏布局无溢出。
2. 完成浅色、深色、自定义主题及 900px/宽屏预览，检查窗口按钮不会被拖动区吞掉，侧栏动画不遮挡顶栏。
3. 全量 Flutter 测试、dart analyze、格式及 diff 检查；Windows Debug 构建。
4. 使用普通 Downloads 目录中的完整程序包验证无系统默认标题栏、窗口操作与正常退出；仅关闭本轮自行启动的测试进程。保留用户作品哈希，不删除锁文件，不修改 ACL，不结束已有进程。
5. 交付完整目录中的可执行文件入口；不直接交付低完整性标签的 build 目录程序，不要求单独移动 exe。

## 规格自检

设计中不包含额外的一条独立标题栏，不更换现有主题，不绕过退出守卫；当前用户要求的左右布局均已明确。实现范围、例外行为和验收方式已列出，无待定项。
