## 4. P1：第一阶段结构性重构

### 4.1 提取书库写入／导出协调器

建议新增 `lib/state/library_operation_gate.dart`，修改 `lib/state/library_controller.dart`：

- [ ] 将普通写入计数、导出预约、等待写完和拒绝后续写入的逻辑集中到一个明确边界。
- [ ] 普通书库变更按顺序执行，避免多个事务基于旧快照交错提交。
- [ ] 导出预约必须在等待之前生效，后续写入不得越过导出。
- [ ] 将 `noteChapterSaved()` 触发的摘要磁盘写入纳入同一协调边界。
- [ ] 保持 `EditorController` 的导航队列，不以全局大锁替代现有全部队列。
- [ ] 保持 `WorkspaceController` 的 UI 防重入职责，不把所有状态塞进协调器。
- [ ] 明确关闭、异常和嵌套调用行为，避免死锁及错误吞没。
- [ ] 运行 P0 新增的并发测试及全部既有测试。

目标锁层次：

1. `WorkspaceController`：防止 UI 重复操作。
2. `EditorController`：编辑导航与结构操作串行化。
3. 书库写屏障：普通变更串行，导出预约后等待既有写入并阻止后来者。

### 4.2 从 `LibraryController` 提取书内结构服务

建议新增 `lib/state/book_structure_service.dart`：

- [ ] 迁移卷章创建：`appendChapter()`、`appendVolume()`。
- [ ] 迁移卷章删除：`deleteChapter()`、`deleteVolume()`。
- [ ] 迁移卷章重命名：`renameVolume()`、`renameChapter()`。
- [ ] 迁移排序与跨卷移动：`relocateChapter()`、`reorderVolume()`、`moveChapter()`、`moveVolume()`。
- [ ] 迁移编号写入：`setNumbering()`、`setVolumeNumberingMode()`、`setGlobalNumbering()`。
- [ ] 将快照复制、规范化、提交、真实状态同步和对象身份保持逻辑放入清晰的共享边界，避免复制两套实现。
- [ ] 保留 `_apply()` 所保证的对象身份语义，编辑器不得因服务拆分持有失效卷章引用。
- [ ] 保留摘要失败后的真实落盘状态同步与 `blockedBooks` 保护语义。
- [ ] `LibraryController` 暂时作为兼容外观委托给新服务，避免一次性重写所有 UI 调用方。
- [ ] 书架加载、排序、作品 CRUD、最近章节等书架职责暂时留在 `LibraryController`。
- [ ] 新服务全部写入经书库写屏障进入，不建立第二套并发规则。
- [ ] 逐步迁移调用方后，再删除兼容外观中的重复入口。

### 4.3 拆分 `chapter_pane.dart`

建议拆为目录主组件、卷名内联编辑组件、拖放交互组件；具体文件名以实施时最小依赖方案为准：

- [ ] 提取卷名内联编辑：草稿、Enter／失焦提交、Esc 取消、IME 组合态、失败留稿和重复提交合并。
- [ ] 提取拖放交互：移动模式、落点校验、键盘移动、拖动状态和边缘自动滚动。
- [ ] 目录主组件只保留布局、卷章展示和组件协调。
- [ ] 菜单命令统一经 `WorkspaceController` 或明确的应用服务进入，减少 UI 直接触达 `LibraryController`。
- [ ] 保留稳定 ID 的导出目标，不在菜单异步返回后依赖已变化的卷章对象位置。
- [ ] 保留现有 ValueKey、语义标签、焦点顺序和测试定位方式。
- [ ] 覆盖宽屏／窄屏、折叠卷、空卷、跨卷移动、Esc、方向键和长目录边缘滚动。
- [ ] 不在本阶段顺带重做视觉样式或更换状态管理框架。
